# **دیده‌بان نوبت پزشکان**

ابزار سبک پایتونی که صفحهٔ نوبت‌دهی پزشکان را در پلتفرم‌های پشتیبانی‌شده پایش می‌کند، وضعیت نوبت‌های آزاد را به‌صورت مقایسه‌ای در ترمینال نمایش می‌دهد و هنگام باز شدن نوبت جدید، از طریق تلگرام اطلاع می‌دهد.

پلتفرم‌های پشتیبانی‌شده: **دکتورتو** (`doctoreto.com`) و **پذیرش۲۴** (`paziresh24.com`). افزودن پلتفرم‌های دیگر از طریق مشارکت جامعه ممکن است.

## **قابلیت‌ها**

* پایش هم‌زمان یک پزشک در هر پلتفرم پشتیبانی‌شده
* نمایش مقایسه‌ای نوبت‌های آزاد در ترمینال
* وضعیت پایش مستقل برای هر ارائه‌دهنده و هر پزشک
* اطلاع‌رسانی تلگرام همراه با لینک رسمی رزرو
* جلوگیری از اعلان‌های تکراری برای یک نوبت
* خطا در یک پلتفرم هرگز نتیجهٔ پلتفرم دیگر را پنهان نمی‌کند
* ذخیرهٔ محلی تنظیمات و ارتقای خودکار تنظیمات قدیمی تک‌پزشکی
* امکان پیکربندی مجدد پزشکان در هر زمان
* بازهٔ بررسی قابل تنظیم
* پشتیبانی از نام‌ها و آدرس‌های فارسی/یونیکد
* مناسب Termux
* فقط با کتابخانهٔ استاندارد پایتون
* بدون رزرو خودکار — رزرو همیشه در سایت رسمی انجام می‌شود

## **پلتفرم‌های پشتیبانی‌شده**

|  **پلتفرم**  |  **وضعیت**  |  **منبع داده**  |
|---|---|---|
|  دکتورتو (`doctoreto.com`)  |  ✅ پشتیبانی می‌شود  |  صفحهٔ عمومی پزشک (`__NEXT_DATA__`)  |
|  پذیرش۲۴ (`paziresh24.com`)  |  ✅ پشتیبانی می‌شود  |  صفحهٔ عمومی پزشک (`samanDoctorAvailabilityStatus`)  |
|  پلتفرم‌های دیگر  |  🤝 از مشارکت‌های جامعه استقبال می‌شود  |  —  |

## **پیش‌نیازها**

* Termux روی اندروید (یا هر سیستم با پایتون ≥ ۳٫۱۰)
* اتصال اینترنت
* صفحهٔ پزشک در یکی از پلتفرم‌های پشتیبانی‌شده
* یک ربات تلگرام

در Termux نیازی به نصب دستی پایتون نیست؛ اسکریپت راه‌اندازی وجود پایتون را بررسی و در صورت نیاز نصب می‌کند.

## **نصب**

مخزن را کلون کنید:

```
git clone https://github.com/hosseinzamaninasab/doctor-appointment-watcher.git
cd doctor-appointment-watcher
```

اسکریپت راه‌اندازی را اجرا کنید:

```
chmod +x setup.sh
./setup.sh
```

این اسکریپت محیط Termux را آماده و برنامه را اجرا می‌کند. در لینوکس/مک می‌توانید مستقیماً اجرا کنید:

```
python3 appointment_watcher.py
```

## **اجرای اول**

در اولین اجرا، چون تنظیماتی وجود ندارد، راه‌اندازی خودکار شروع می‌شود.

از شما پرسیده می‌شود:

1. آدرس صفحهٔ پزشک برای هر پلتفرمی که می‌خواهید پایش کنید (با Enter روی خط خالی پایان دهید)
2. نام پزشکان (به‌صورت خودکار از صفحه تشخیص داده می‌شود؛ فارسی پشتیبانی می‌شود)
3. توکن ربات تلگرام
4. گفتگوی تلگرام

مثال:

```
=== Doctor Appointment Watcher Setup ===

Supported providers: doctoreto, paziresh24

Doctor URL:
> https://doctoreto.com/doctor/tehran/...

Detected doctor name: نام و نام خانوادگی دکتر
Doctor ID extracted automatically: ...

Doctor URL (empty line to finish):
> https://paziresh24.com/dr/دکتر-...

Doctor URL (empty line to finish):
>

Telegram Bot Token:
> ********

Open your bot in Telegram and press Start.

Setup completed successfully.
```

می‌توانید فقط یک پلتفرم یا هر دو را پایش کنید — یک پزشک برای هر پلتفرم. اگر آدرس دومی برای همان پلتفرم بدهید، پزشک قبلی جایگزین می‌شود.

تنظیمات به‌صورت محلی ذخیره می‌شود تا هر بار وارد نکنید. تنظیمات قدیمی تک‌پزشکی به‌صورت خودکار ارتقا می‌یابد و چیزی از دست نمی‌رود.

## **اجرای دیده‌بان**

پس از راه‌اندازی اولیه:

```
./setup.sh
```

یا:

```
python appointment_watcher.py
```

اگر تنظیمات موجود باشد، منوی زیر نمایش داده می‌شود:

```
=== Doctor Appointment Watcher ===

1) Start watcher
2) Configure doctors
3) Exit
```

### **شروع دیده‌بان**

گزینهٔ `1` را انتخاب کنید. در هر چرخه همهٔ ارائه‌دهنده‌ها بررسی و نتیجه مقایسه‌ای چاپ می‌شود:

```
=== Appointment comparison (2026-11-13 11:19) ===

doctoreto — دکتر علی رضایی
  ❌ No open appointments

paziresh24 — پزشک نمونه
  ✅ 2 open slot(s):
  • مطب نمونه | 2026-12-01 10:30
  • ویزیت آنلاین پذیرش24 | 2026-11-14 15:00
  Book on the official site: https://paziresh24.com/dr/...
```

اگر یک ارائه‌دهنده خطا بدهد (مشکل شبکه یا تغییر ساختار صفحه)، نتیجهٔ ارائه‌دهندهٔ دیگر همچنان نمایش و پایش می‌شود:

```
doctoreto — دکتر علی رضایی
  ⚠️ Check failed: Connection failed: HTTP Error 404: Not Found
```

### **بررسی یک‌باره**

```
python appointment_watcher.py --once
```

همهٔ ارائه‌دهنده‌ها یک بار بررسی، نتیجهٔ مقایسه‌ای چاپ و برنامه خارج می‌شود. برای تست یا استفاده در cron مناسب است.

### **پیام تست تلگرام**

```
python appointment_watcher.py --test
```

### **پیکربندی پزشکان**

گزینهٔ `2` راه‌اندازی را دوباره اجرا می‌کند؛ تنظیمات قبلی جایگزین و وضعیت پایش بازنشانی می‌شود.

### **خروج**

گزینهٔ `3`.

## **توقف دیده‌بان**

`Ctrl + C` را بفشارید.

در Termux وقتی کلید Ctrl وجود ندارد، معمولاً `Volume Down + C` کار می‌کند.

## **نحوهٔ کار**

```
آدرس پزشکان (یکی برای هر ارائه‌دهنده)
    ↓
تشخیص خودکار ارائه‌دهنده از روی آدرس
    ↓
دریافت صفحهٔ عمومی پزشک (برای هر ارائه‌دهنده)
    ↓
استخراج نوبت‌های آزاد (برای هر ارائه‌دهنده)
    ↓
نرمال‌سازی به مدل مشترک نوبت
    ↓
مقایسه با وضعیت قبلی همان هدف
    ↓
نوبت جدید؟
   ↙              ↘
 بله               خیر
  ↓                 ↓
اعلان تلگرام     ادامه
(لینک رسمی)
```

* هر جفت «ارائه‌دهنده + پزشک» **وضعیت مستقل** خود را دارد؛ بنابراین نوبت‌های یک ارائه‌دهنده هرگز اعلان‌های ارائه‌دهندهٔ دیگر را ساکت نمی‌کند.
* یک فایل وضعیت محلی از اعلان تکراری جلوگیری می‌کند: نوبت‌های یکسان یک بار اعلام می‌شوند؛ با بسته شدن نوبت‌ها اثر انگشت بازنشانی می‌شود تا نوبت واقعاً جدید، اعلان جدید بگیرد.
* اگر یک ارائه‌دهنده مدام خطا بدهد (حدود یک ساعت خطای پیاپی)، یک هشدار تلگرام ارسال می‌شود.

## **تنظیمات و حریم خصوصی**

تنظیمات در `~/.config/doctoreto-watcher/config.json` ذخیره می‌شود (مسیر تاریخی برای سازگاری حفظ شده است).

```json
{
  "version": 2,
  "check_interval_seconds": 600,
  "bot_token": "...",
  "chat_id": "...",
  "targets": [
    {
      "provider": "doctoreto",
      "doctor_name": "نام دکتر",
      "doctor_id": "...",
      "doctor_url": "https://doctoreto.com/doctor/..."
    },
    {
      "provider": "paziresh24",
      "doctor_name": "نام دکتر",
      "doctor_id": "دکتر-...",
      "doctor_url": "https://paziresh24.com/dr/..."
    }
  ]
}
```

فایل تنظیمات در سیستم‌عامل‌های پشتیبانی‌شده با مجوز دسترسی محدود حفاظت می‌شود.

**هرگز فایل تنظیمات یا توکن ربات خود را به اشتراک بگذارید یا کامیت نکنید.**

اگر توکن ربات افشا شد، بلافاصله آن را از BotFather باطل کنید.

## **رفع اشکال**

| نشانه | معنی |
|---|---|
| `⚠️ Check failed: ...` در خروجی مقایسه | آن ارائه‌دهنده قابل بررسی نبود (شبکه، تایم‌اوت یا تغییر ساختار صفحه). ارائه‌دهندهٔ دیگر به کار خود ادامه می‌دهد. |
| هشدار تلگرام «چند بار پیاپی با خطا مواجه شده است» | یک ارائه‌دهنده حدود یک ساعت به‌طور پیاپی خطا داده است. اتصال اینترنت را بررسی کنید. |
| `Could not find ... The website structure may have changed.` | ساختار صفحهٔ ارائه‌دهنده با انتظار تطابق ندارد؛ لطفاً issue ثبت کنید. |
| اعلانی نمی‌آید ولی در مرورگر نوبت دیده می‌شود | اعلان همان نوبت‌ها قبلاً ارسال شده (جلوگیری از تکرار). برای نوبت جدید صبر کنید یا `state.json` را حذف کنید. |
| `Configuration is incomplete` | دوباره `python appointment_watcher.py --setup` را اجرا کنید. |

## **محدودیت‌های شناخته‌شده**

* نوبت‌های دکتورتو از دادهٔ تعبیه‌شدهٔ Next.js در صفحهٔ عمومی خوانده می‌شود؛ تغییر طراحی سایت می‌تواند تجزیه را بشکند تا آداپتور به‌روز شود.
* نوبت‌های پذیرش۲۴ از دادهٔ `samanDoctorAvailabilityStatus` صفحهٔ عمومی خوانده می‌شود: این داده نزدیک‌ترین زمان قابل رزرو هر مطب/ویزیت آنلاین را می‌دهد، نه فهرست کامل همهٔ نوبت‌ها.
* قیمت نوبت در صفحهٔ عمومی هیچ‌یک از ارائه‌دهنده‌ها موجود نیست؛ مدل قیمت را «نامشخص» نگه می‌دارد نه حدسی.
* نوبت‌ها هر لحظه ممکن است تغییر کنند؛ دیده‌بان فقط چیزی را که صفحه در زمان بررسی نشان داده گزارش می‌دهد و هرگز رزرو نمی‌کند.

## **امنیت**

هرگز این‌ها را کامیت نکنید:

* توکن ربات تلگرام
* شناسهٔ خصوصی گفتگو
* کوکی یا اعتبارنشست
* کلیدهای API
* فایل‌های تنظیمات شخصی

این پروژه هیچ پروندهٔ پزشکی یا سابقهٔ درمانی ذخیره نمی‌کند، به هیچ ارائه‌دهنده‌ای وارد نمی‌شود و هیچ اعتباری به سایت ارائه‌دهنده‌ها نمی‌فرستد.

## **استفادهٔ مسئولانه**

این پروژه برای پایش شخصی نوبت است.

کاربران مسئول رعایت این موارد هستند:

* شرایط استفاده از وب‌سایت‌ها
* محدودیت‌های نرخ دسترسی
* قوانین و مقررات مرتبط
* هرگونه محدودیت اعمال‌شده توسط پلتفرم پایش‌شده

از بازه‌های بررسی منطقی استفاده کنید (پیش‌فرض ۱۰ دقیقه) و از ترافیک غیرضروری بپرهیزید.

این پروژه به‌صورت خودکار نوبت رزرو نمی‌کند.

## **افزودن پلتفرم جدید**

برنامه ارائه‌دهنده را به‌طور خودکار از روی آدرس پزشک تشخیص می‌دهد.

مشارکت‌کنندگان می‌توانند منطق اختصاصی وب‌سایت را برای این موارد پیاده‌سازی کنند:

* تشخیص پلتفرم (نام دامنه‌ها)
* اعتبارسنجی و نرمال‌سازی آدرس پزشک
* شناسایی پزشک
* استخراج اطلاعات نوبت از صفحهٔ عمومی
* نرمال‌سازی نتیجه به قالب مشترک نوبت

منطق مشترک پایش، تنظیمات و تلگرام مستقل از پلتفرم باقی می‌ماند. برای راهنما `CONTRIBUTING.md` و برای نمونهٔ مستند آداپتور `providers/paziresh24.py` را ببینید.

## **مشارکت**

از مشارکت استقبال می‌شود.

برای افزودن پلتفرم جدید:

1. مخزن را Fork کنید
2. یک شاخهٔ قابلیت بسازید
3. منطق اختصاصی پلتفرم را در `providers/` پیاده کنید
4. تست‌ها را همراه با فیکسچر صفحات واقعی (`tests/fixtures/`) اضافه کنید
5. مستندات پلتفرم‌های پشتیبانی‌شده را به‌روز کنید
6. Pull Request بفرستید

مثال:

```
git checkout -b feature/add-new-platform
```

لطفاً منطق اختصاصی پلتفرم را ایزوله نگه دارید و از تغییرات غیرضروری در هستهٔ برنامه بپرهیزید.

## **ساختار پروژه**

```
doctor-appointment-watcher/
│
├── appointment_watcher.py       # نقطهٔ ورود CLI و هماهنگی برنامه
├── providers/
│   ├── __init__.py              # ثبت ارائه‌دهنده‌ها و تشخیص از روی URL
│   ├── base.py                  # اجزای مشترک HTTP و Next.js و قرارداد ارائه‌دهنده
│   ├── model.py                 # مدل مشترک نوبت بین ارائه‌دهنده‌ها
│   ├── doctoreto.py             # آداپتور دکتورتو
│   └── paziresh24.py            # آداپتور پذیرش۲۴ (منبع داده مستند)
├── tests/                       # تست‌های unittest (آفلاین با HTTP شبیه‌سازی‌شده)
│   ├── fixtures/                # صفحات واقعی ثبت‌شدهٔ ارائه‌دهنده‌ها
│   └── test_*.py
├── setup.sh
├── README.md
├── README.fa.md
├── CONTRIBUTING.md
└── LICENSE
```

اجرای تست‌ها:

```
python -m unittest discover -s tests -t .
```

تست‌ها کاملاً آفلاین هستند (HTTP و تلگرام شبیه‌سازی شده‌اند) و شامل صفحات واقعی ثبت‌شده از هر دو ارائه‌دهنده‌اند.
